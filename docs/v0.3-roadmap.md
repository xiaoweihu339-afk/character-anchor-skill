# v0.3 Roadmap

Version `0.3.0` moves Character Anchor Skill from a text-first library MVP toward a media-first product workflow.

## Why v0.3 Exists

Real user testing showed that the first useful question is not "describe the character manually." The real starting point is usually:

> I have a folder of images and videos. Help me turn it into reliable character references.

The previous version had a clean file structure and prompt compiler, but it did not yet solve the hardest product problems:

- large media folders may be sampled too aggressively
- the system must say what it actually inspected
- source references can include the wrong person, small faces, occlusion, hats, text overlays, or poor lighting
- chat image previews may fail, so local review artifacts are needed
- generated golden images must not be promoted unless they really resemble the target
- the repo does not yet contain a built-in identity-preserving image generator

## v0.3 Contract

v0.3 is a media-first scaffold, not a full generation engine.

Implemented in this repository:

- `scripts/audit_media_coverage.py`: inventories a raw media folder and reports that inventory is not visual review.
- `scripts/build_review_gallery.py`: creates local HTML galleries for candidate/reference review.
- `scripts/update_face_lock.py`: records face geometry ratios and qualitative face locks before golden-candidate generation.
- `scripts/generate_golden.py`: creates structured request payloads for external identity-preserving image workflows.
- `scripts/record_golden_feedback.py`: records user feedback for generated golden candidates.
- README and SKILL guidance now start from media-first usage instead of long manual character entry.

Still outside this repository:

- automatic face detection and identity clustering
- automatic face embeddings and similarity scoring
- automatic video frame extraction
- direct ComfyUI, InstantID, PuLID, IP-Adapter, or Flux execution
- automatic promotion into `references/golden/`

## Recommended User Flow

1. Create or copy a private lab folder.
2. Put authorized raw media in that private lab.
3. Run `audit_media_coverage.py` so the user sees file counts and review limits.
4. Build review galleries for the candidate images that survived hard-defect screening.
5. Create a face geometry lock from the selected references:
   - face length to width
   - eye spacing
   - brow-to-eye distance
   - mouth width
   - jaw width
   - cheekbone width
6. Prepare an external golden-generation request with explicit coverage targets:
   - front face
   - 3/4 face
   - 90-degree profile
   - back view
   - upper body
   - full body
   - long shot
   - motion reference
7. Generate candidates in an external identity-preserving workflow.
8. Record user likeness feedback and tune the face lock when repeated drift appears.
9. Promote only authorized, safe, identity-stable outputs into `references/golden/`.

By default, generation request payloads should reference only approved golden references. Private experiments may use unvalidated references, but those payloads must stay out of public release material and should not be promoted without review.

## Next Version Direction

The next major step should be a real visual engine adapter. A practical path:

- add optional local dependencies for face detection and frame extraction
- create `extract_face_profile.py`
- add identity-cluster review
- upgrade `update_face_lock.py` from manual/AI-assisted ratios to landmark-derived measurements
- add provider-specific payload templates for ComfyUI/InstantID/PuLID
- add automatic candidate routing to `outputs/candidates/` and `outputs/failed/`
- keep all real-person materials private by default
